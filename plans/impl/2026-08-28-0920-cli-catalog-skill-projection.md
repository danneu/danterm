# Make SKILL.md's CLI contract a projection of the catalog (CLI-7, CLI-9, CLI-11)

Source: `docs/scratch/2026-08-26-improvement-audit.md`, findings CLI-7, CLI-9, CLI-11
(Wave 11, "Make the IPC and CLI contracts enforce themselves").

## 1. Problem and evidence

`integrations/danterm/SKILL.md` is the source of truth for the `danterm` CLI, but only
its command synopsis is a gate-checked projection (`CLISkillSynopsisRegion`,
`DanTermSkillSynopsisGenerator --check` in `LINT_STEPS`). The rest is prose that has
rotted:

- `SKILL.md:833` prints `"version":3`; `paneTapeStreamVersion` is 6 and `SKILL.md:683`
  says 6.
- The "CLI stdout shapes" table (`SKILL.md:1030`) opens "Only these subcommands print to
  stdout" and omits `doctor` and `help`, which print locally from `cli/main.swift`.
- The pane grid bound is written three times as English: `SKILL.md:589`,
  `CLICommandCatalog.swift:250` (`pane resize` help), and the enforcing ranges in
  `lib/DanTermCore/.../PaneGridOverride.swift`, which are internal to `DanTermCore` so
  the catalog cannot read them. `defaultHistoryBudgetBytes` is likewise a literal in
  `SKILL.md:668` and `CLICommandCatalog.swift:259`.
- `cli-tests/UsageTextTests.swift:37-38` pins the literals `Columns 2-1024` and
  `default 262144`, so a constant change fails a test that is then "fixed" by editing
  the literal.
- `pane zoom` help says "Prints the tab's resulting zoom state"; SKILL.md tells callers
  to read `pane.isZoomed`.

Load-bearing premises: the output mode of a command is assigned per parser branch in
`CLIParser.swift` (`outputMode: .json` etc.), not on `CLICommandDescriptor`; and the
three local routes (`help`, `skill`, `doctor`) write stdout directly in `cli/main.swift`
outside any output-mode path. The stdout table cannot be a projection of anything until
the catalog owns that fact and execution obeys it.

## 2. Decision

Make the catalog's output contract the thing that controls execution, then project
SKILL.md from it.

- `CLICommandDescriptor` owns the static **output contract** of its command: the kind of
  stdout it produces (nothing, one JSON value, raw text, a record stream, or a local
  report) plus the one-line shape description SKILL.md's table currently carries by
  hand. `help`, `skill`, and `doctor` declare theirs like every other entry.
- A contract may offer named variants chosen per invocation (today `pane tape`'s
  replay/inspect format; a `doctor --json` projection is the same shape). The parser
  selects only the variant; the kind and documented form of each variant live on the
  descriptor, and the stdout table documents every variant of a row.
- Parsing no longer chooses an output mode. It returns the request plus the selected
  variant, if the contract has any.
- One execution boundary in the CLI applies the descriptor's contract to the result,
  whether that result came over IPC or from a local handler. Local handlers return
  their output and exit status; they do not write stdout themselves.
- The generator owns a **set of named generated regions** in SKILL.md, all checked and
  updated by the existing `DanTermSkillSynopsisGenerator` step and `just
  update-danterm-skill`: the command synopsis (bytes unchanged), a protocol-constants
  region (`paneTapeStreamVersion`, the default sync-history budget, the grid column and
  row ranges), and the stdout-shapes table.
- The four prose sites that state those values today (`SKILL.md:589`, `:668`, `:683`,
  `:833`) become references to the constants region or drop the number. Explanatory
  prose stays hand-written.
- The grid ranges move into `DanTermProtocol` as public constants. `PaneGridOverride`
  stays the sole validator and `IpcDispatch`'s rejection message keeps reading them.
- Help strings that state a constant interpolate it (`pane resize` ranges, `pane tape`
  default budget). `pane zoom` help names the pane, not the tab.

Behavioral scope: `danterm help` wording, SKILL.md generated bytes, gate failure on a
stale region, and the CLI's internal output path. No wire change; every command's
observable stdout, stderr, and exit status are unchanged.

Moving surface: other Wave 11 tabs (`doctor --json`, a `TodoText` parse error) add or
change catalog entries. They declare their output on the descriptor and run
`just update-danterm-skill`; region bytes are regenerated, never hand-merged. Whoever
lands second reruns the generator.

## 3. Invariants

- I1. Every command that writes to stdout on success appears in SKILL.md's stdout table
  with its declared shape, and no command that prints nothing appears there.
- I2. The only path by which the CLI writes a command's stdout is the one that reads
  the command's descriptor contract; a parser branch or a local handler cannot choose
  an output kind of its own.
- I3. The stream version, default sync-history budget, and grid ranges are rendered
  from their declarations into the generated constants region, and the prose sites
  that used to state them refer to that region instead of carrying a number.
- I4. The grid bound is declared once; the help text, the daemon rejection message, and
  the validator read the same declaration.
- I5. A malformed or stale generated region fails `--check` with a message naming which
  region, for every region in the set.

## 4. Proof obligations

- PO1 (I1, I5): `DanTermProtocolTests` -- a document whose stdout region omits an entry
  with non-empty output, or lists an entry with none, is rejected as stale for that
  region; the rendered region names `doctor`, `help`, and `skill`.
- PO2 (I2): `cli-tests` black-box -- for every route, including the three local ones,
  a successful invocation's stdout is empty exactly when the descriptor declares no
  output, and the kind of what it prints matches the declared variant the invocation
  selected. Existing
  characterization tests for each command's stdout, stderr, and exit status pass
  unchanged.
- PO3 (I3): `DanTermProtocolTests` -- the constants region contains the rendered
  `paneTapeStreamVersion`, `defaultHistoryBudgetBytes`, and both grid ranges. A test over
  the checked-in SKILL.md asserts each of the four former prose sites now carries the
  region reference and no numeric literal. The gate's existing `--check` step covers drift (no new
  `LINT_STEPS` entry; GATE-3's self-test rule is already satisfied by that step).
- PO4 (I4): `cli-tests/UsageTextTests` asserts `pane resize` help against the rendered
  constants, not literals; `DanTermCoreTests` edge rejection tests pass unchanged.
- PO5: `UsageTextTests` -- `pane zoom` help says the pane's zoom state.
- PO6 (I5): the malformed-marker cases (missing, duplicate, reversed) and the stale case
  are exercised for every region in the set, and each failure names that region.
- PO7: `just update-danterm-skill` followed by `--check` is a fixed point, and `--check`
  on the committed SKILL.md passes.

## 5. Non-goals / accepted risks / rejected ideas

- Non-goal: generating any explanatory prose in SKILL.md. Only tables and constants are
  generated.
- Non-goal: enforcing `targetPolicy` (CLI-4/5/6, another tab).
- Rejected: a grep-based lint on `"version":N` in SKILL.md -- catches one constant,
  leaves the table hand-synced.
- Rejected: keeping per-branch `outputMode` in the parser beside a descriptor
  declaration and guarding the pair with a consistency test -- two declarations of one
  fact, and the local routes escape the guard.
- Accepted risk: the "follow cap" the audit names does not exist as a constant; the
  constants region carries the four that do.

## 6. Implementation discretion

- Marker spelling for the new regions and whether the generator keeps its current
  executable name.
- The shape of the descriptor's contract type and of the value local handlers return.
