# OSC 133 semantic prompts + prompt redraw on resize (Swift engine)

## Context

### Problem

With `DANTERM_TERMINAL_BACKEND=swift`, repeatedly opening and closing a
side split corrupts the pane that stays open: one stale copy of the
two-line zsh prompt accumulates above the live prompt per open/close
cycle, each stale fragment shifted one more column (a "staircase"), the
right-aligned segment truncated one more character, and the live prompt
bumped down one row per cycle. Copying the region yields one giant
logical line. Under the libghostty backend the same actions stay clean.

### Root cause and how it was pinned down

Diagnosed by capturing the real zsh prompt's byte stream in a PTY
(answering the shell's startup queries) and replaying those exact bytes
plus resizes directly into `TerminalCore.Terminal`:

- A single shrink->grow resize round trip is clean: reflow, cursor
  attachment, and the shell's SIGWINCH repaint all land correctly. The
  core reflow math is not the bug.
- A gradual width sweep -- many intermediate widths with the shell's
  repaints interleaved, which is exactly what a split open/close
  produces (`SwiftTerminalSessionView.synchronizeGeometry` issues one
  resize per AppKit layout pass) -- reproduces the corruption exactly.

Two causes, one primary:

1. **Missing OSC 133 prompt-redraw handling (primary).** The shell
   emits `ESC]133;A` at prompt start and, on each SIGWINCH, repaints
   only its own two prompt rows (`\r \r ESC[A ESC[K ... ESC[J` -- up
   one row from the cursor, erase, rewrite). After the engine reflows
   at a new width, the old full-width prompt line occupies two rows, so
   the repaint lands one row low and strands the old head row above the
   shell's repaint window -- permanently. Ghostty avoids this: on every
   primary-screen resize, when the cursor sits on an OSC 133
   prompt/input line, it clears the prompt rows to blank cells _before_
   reflowing (`.ghostty-src/src/terminal/Screen.zig` resize,
   `shell_redraws_prompt` default true), because a shell that emits
   OSC 133 repaints its prompt after SIGWINCH. The Swift engine does
   not parse OSC 133 at all; `docs/terminal-capabilities.md` currently
   lists it as denied.
2. **Stale soft-wrap glue (amplifier).** The stranded head row keeps
   `isSoftWrapped = true` into the row the shell erases and rewrites,
   so reflow joins stale head + new prompt into one logical line; each
   subsequent reflow re-packs the growing chain, shifting content by
   the per-step width delta and pushing the prompt down. Ghostty has
   identical EL/wrap-flag semantics and escapes only because the prompt
   rows are cleared before reflow ever sees them.

### Desired outcome

Split open/close (and any resize) over an OSC 133-emitting shell leaves
the pane visually identical to libghostty: no stale prompt fragments, no
prompt drift, prompt anchored where the shell repaints it.

## Decision

Port Ghostty's OSC 133 semantic-prompt tracking and prompt-redraw-on-
resize behavior into `TerminalCore`, engine-internal only. This is a
deliberate capability-contract change: OSC 133 moves from the denied
list to a supported protocol, sanctioned by the "additional harmless
protocols may be supported when required by the accepted application
matrix" clause in `plan-terminal-engine/10-protocols-shell-integration.md`.
The soft-wrap/EL semantics are intentionally untouched -- Ghostty's are
identical, and parity means clearing prompt rows before reflow, not
changing wrap flags.

Scope of the port (Ghostty-parity unless listed under Deviations):

- **Grammar** (`.ghostty-src/src/terminal/osc/parsers/semantic_prompt.zig`):
  actions `A` (fresh line + new prompt), `B` (input, explicit clear),
  `I` (input, clears at end of line), `C` (output; plus the fish
  column-0 un-prompt heuristic), `D` (command end -> output), `L`
  (fresh line, no options permitted), `N` (alias of `A`), `P` (prompt
  start without fresh line). A bare action is valid; for every action
  except `L`, any byte after the action letter must be `;` or the whole
  command is ignored. `L` is special-cased: it takes no options at all,
  so _any_ trailing byte -- including `;` -- makes it a malformed
  command. Options
  are lenient `key=value` pairs, read per action (Ghostty parity):
  `k=` (i/r -> prompt, c/s -> continuation) is read only by `A`/`N`
  and `P`; `redraw=` (`0`/`1`/`last`; absent leaves the flag
  unchanged) is read only by `A`/`N`. `B`, `I`, `C`, `D`, and `L` read
  no options, so a recognized-but-irrelevant option on them (e.g.
  `B;redraw=0`, `C;k=s`) changes no state. `aid`, `cl`,
  `click_events`, `special_key`, `cmdline`, `cmdline_url`, `err`, and
  `D`'s bare exit-code field are parsed and ignored on every
  option-bearing action; unknown or malformed options are skipped
  without invalidating the command.
- **State**: cursor-level semantic content (output/prompt/input + a
  clears-at-EOL bit), a per-row semantic-prompt marker on `GridRow`
  (none/prompt/continuation), and a terminal-wide redraw capability
  flag defaulting to full-redraw. No per-cell semantic state (see
  Deviations). Nothing added to the DECSC saved cursor (Ghostty
  parity). The primary screen's semantic cursor state survives the
  alternate screen via `InactivePrimaryScreen`, mirroring Ghostty's
  per-screen cursors.
- **Continuation stamping** in both paths that start a new visual row
  while printing prompt/input content: soft wrap stamps the new row as
  a prompt continuation when content is prompt; hard newline
  (LF/IND/NEL) stamps continuation unless the clears-at-EOL bit is set,
  in which case content snaps back to output.
- **Resize clear** (first step of primary-screen resize, both the
  primary-only and alternate-active branches; alternate grid never
  cleared; runs for height-only resizes too -- verified Ghostty
  behavior): when the redraw flag is not disabled and the cursor's
  semantic content is not output, find the prompt start by walking up
  from the cursor row -- skipping unmarked rows, following continuation
  chains to their topmost `prompt` row -- then blank the _cells_ of
  every row from the prompt start to the bottom of the active area, in
  place: row count, cursor, `isSoftWrapped`, and the semantic markers
  are all preserved. `redraw=last` blanks only the cursor's row. If no
  start is found, skip (safe no-op).
- **Flag lifecycle**: reflow carries the per-row marker to destination
  rows (Ghostty parity; load-bearing for back-to-back resizes with no
  interleaved repaint). Whole-row erases (ED paths, hard reset row
  sweep) reset the marker to none; EL does not. RIS resets all semantic
  state including the redraw flag; DECSTR does not touch it.

### Deviations from Ghostty (documented in code and capability doc)

- No per-cell semantic content: Ghostty stamps cells for
  selection/click features that are out of scope; its resize clear
  reads only cursor + row state, which this port keeps.
- The prompt-start walk-up is viewport-bounded (Ghostty can walk into
  history). A prompt taller than the screen degrades to clearing from
  the topmost qualifying viewport row -- never corrupts.

## Invariants

- I1: After any resize with the cursor on an OSC 133 prompt/input line
  and redraw not disabled, no cell content from the pre-resize prompt
  block survives within the clear range, and rows outside that range
  are untouched. The range is redraw-mode-scoped: full redraw covers
  the whole prompt block (prompt start through the bottom of the
  active area), `redraw=last` covers only the cursor's row.
- I2: With the cursor on command output (or redraw disabled, or no
  OSC 133 seen), resize behavior is byte-for-byte identical to today's
  reflow -- no clearing.
- I3: The alternate screen is never prompt-cleared; the primary's
  semantic state survives an alternate-screen round trip.
- I4: A malformed OSC 133 _command_ is an atomic no-op: an
  unrecognized action letter, a non-`;` byte after an option-bearing
  action letter, or any trailing byte at all after `L`. A valid
  command whose option list contains unknown or malformed options
  still applies its action and every option it does recognize -- e.g.
  `133;A;future=x` starts a prompt normally. Feeding a stream whole vs
  split at any byte offset yields equal terminals (existing
  chunk-invariance contract extended to OSC 133).
- I5: The interleaved-repaint width sweep (the reproduced staircase)
  converges to exactly one prompt instance at its anchored position.

## Test plan

TDD: staircase regression first (fails today), then parser/stamping,
then resize-clear, then the captured fixture. Gate:
`swift test --package-path lib/TerminalCore` (inside `just test`).

- **Staircase regression (I5)** -- new resize-focused suite: synthetic
  two-line zsh-style prompt (`133;A`, full-width first line, `133;B`),
  multi-step width sweep with the shell's `\r\r ESC[A ESC[K ... ESC[J`
  repaint interleaved after each step; assert exactly one prompt
  instance in `screenText`, expected prompt row, valid grid.
- **Ported Ghostty resize models (I1, I2)** (Screen.zig tests
  ~7343-7501): cursor at prompt -> prompt/input rows blanked, output
  rows intact, cursor preserved; cursor on output -> identical to a
  control terminal fed the same bytes without 133 markers;
  `redraw=last` single- and multi-line prompts -> only cursor's row
  cleared; plus DanTerm additions: redraw-true multiline prompt clears
  all lines, shrink-cols variant, height-only resize clears,
  soft-wrapped prompt clears its whole chain with wrap flags surviving.
- **Parser/stamping (I4)**: grammar acceptance/rejection (bare `A`,
  `Aextra` rejected atomically, `L;aid=foo` and bare `L;` rejected
  while bare `L` is accepted, `133;A;future=x` still starts a prompt, recognized-but-irrelevant
  options on other actions -- `B;redraw=0` leaves the redraw flag
  alone, `C;k=s` leaves content as output), fresh-line motion (mid-line
  vs column 0 vs bottom-row scroll), `redraw=0` suppresses clearing /
  `redraw=1` restores / absent leaves unchanged, `I`+LF ends input at
  EOL, `B`+LF stamps continuation, `C` fish heuristic, and chunk-split
  invariance over an OSC-133-laden stream.
- **Flag lifecycle (I1, I2)**: two resizes back to back with no
  interleaved shell repaint -- the second still clears the reflowed
  prompt block (markers survived reflow); a whole-row erase over the
  prompt rows followed by new unmarked content and a resize leaves that
  content intact (marker cleared); `redraw=0` then DECSTR then resize
  still suppresses the clear (DECSTR does not touch the flag), while
  RIS restores it.
- **Alternate screen (I3)**: prompt on primary, enter alt, resize ->
  alt rows untouched; exit alt -> primary prompt rows blank.
- **Captured-fixture regression (I5)**: convert the real-zsh PTY width-
  sweep capture from the diagnosis session into a
  `NeutralTerminalRecording` fixture (the schema already supports
  interleaved feed + resize events), replayed by the DanTerm recording
  fixture suite under the existing chunk-invariance strategies.
  Re-capture from a live zsh PTY if the original capture is gone.
- **Guard rails**: existing resize/alt-screen/saved-cursor/reset suites
  stay green; add RIS-resets-semantic-state to the reset suite;
  existing no-op-resize bit-identity and byte-split equality tests now
  also exercise the new row field.
- **End-to-end**: `DANTERM_TERMINAL_BACKEND=swift just build-run-optimized`,
  repeat the split open/close ritual against the real zsh prompt, and
  confirm the pane matches libghostty.

## Doc updates (same change)

- `docs/terminal-capabilities.md`: move `osc-133` out of both denied
  lists; add a supported-protocol row with its evidence suites and a
  scope note (semantic prompt state + prompt redraw on resize only; no
  click-to-move, no per-cell semantics, no app-facing events).
- `plan-terminal-engine/10-protocols-shell-integration.md`: add OSC 133
  recognition to the protocol list.
- `plan-terminal-engine/05-unicode-grid-scrollback.md`: carve out the
  "resize does not discard logical content" invariant for prompt/input
  rows blanked under OSC 133 shell-redraw semantics.

## Non-goals

- App-facing semantic events for OSC 133 (state stays engine-internal;
  the OSC 1337 DanTermShell channel is unchanged).
- Click-to-move / `click_events` behavior, prompt navigation
  (jump-to-prompt scrolling), and Ghostty's ED-complete
  "scroll-before-clear at prompt" heuristic.
- Any change to EL/soft-wrap semantics.

## Accepted risks

- Viewport-bounded walk-up (Deviations): prompts taller than the
  screen may clear from the top visible row instead of the true start.
- Per-row marker loss through an exotic reflow degrades to skipping the
  clear on already-blank rows -- stale-content-safe.
